# نجوم البيت — أساس النسخة العامة (Public Starter)

## ما الذي أُنجز؟

- تاب «الإعدادات» واحد، بداخله أقسام مستقلة: الأسرة، الأب والأم، ملفات الأطفال (الاسم والعمر وصورة مضغوطة)، مواقيت الصلاة، البنود (النقاط ومواعيد البداية والإغلاق والتذكير)، قيمة النقطة والعملة، Push، والخصوصية.
- بداية بلا أسماء، ولا صور أطفال حقيقية، ولا معرف أسرة ثابت، ولا مفاتيح Firebase خاصة بالأسرة القديمة.
- عرض معاينة محلية (زر «معاينة الإعدادات») لتجربة الواجهة من دون Firebase. بيانات المعاينة تُحفظ محلياً في هذا المتصفح فقط.
- تصميم PWA وأيقونة عامة غير مرتبطة بأي أسرة، ودعم مظهر فاتح/داكن.
- هيكل التسجيل الذاتي لصاحب الأسرة باستخدام Firebase Authentication، ومجموعة مستقلة لكل أسرة في Firestore (`families/{ownerUid}`)، وقواعد تمنع القراءة بين الأسر.
- نموذج تسجيل الجهاز بـ FCM Web Push، وخدمة Cloud Function لإرسال إشعار عند إنشاء حدث في `events` (بعد النشر والتكوين).

## مهم: حدود النسخة الحالية

هذه **نسخة تأسيسية للاختبار وليست تطبيقاً جاهزاً للبيع على المتاجر**. لا ترفعها مكان تطبيق الأسرة الحالي؛ لأنها واجهة عامة جديدة وليست بديلاً مكتملاً لكل وظائف النسخة الخاصة (الشات، إنجازات اليوم، السجل المالي، الدعوات، والصلاحيات التفصيلية يلزم استكمالها واختبارها). التبديل إلى اتجاه الإنجليزية متاح تجريبياً، لكن الترجمة الإنجليزية الكاملة غير مكتملة. إعدادات الصلاة تحفظ طريقة الحساب والمهلة، لكنها لا تجلب مواقيت فعلية أو تقفل تسجيل الصلاة في هذه النسخة. إعداد مواعيد البنود موجود، لكن محرك إنجاز البنود والمواعيد الفعلية قيد الاستكمال.

Push الحقيقي **ليس شغالاً بمجرد رفع الملفات**. يلزمه مشروع Firebase مستقل ومفتاح VAPID ونشر Cloud Functions وإشعارات أحداث حقيقية، ثم اختبارات على الهواتف. التذكير حسب موعد كل بند في الخلفية يحتاج Scheduler/خدمة خادم إضافية؛ لا يمكن الاعتماد على JavaScript في صفحة مغلقة.

## تجربة أولية على الكمبيوتر

افتح `index.html` عبر خادم محلي (يمكن `python -m http.server 8080` في هذا المجلد)، ثم افتح `http://localhost:8080`. اضغط «معاينة الإعدادات»؛ تعمل واجهة التبويبات محلياً دون سحابة. إذا كانت ملفات SDK الخارجية محجوبة في بيئتك فلن تعمل وحدات Firebase؛ استعمل Chrome مع اتصال بالإنترنت.

## نشر آمن للتجربة (ليس إطلاقاً عاماً بعد)

1. **لا تعدّل مشروع أسرتك الحالي** (مشروع Firebase القديم) ولا المستودع (مستودع الموقع العائلي القديم) قبل عمل نسخة احتياطية. أنشئ مشروع Firebase جديداً للتجارب، ومستودع GitHub جديداً مثلاً `nogoom-public-test`.
2. في Firebase الجديد: فعّل Authentication → Email/Password، وأنشئ Firestore في وضع مقفل، وانشر `firestore.rules` عبر Firebase CLI أو محرر Rules.
3. انسخ إعدادات **Web App للمشروع الجديد فقط** إلى `firebase-config.js`. لا تنسخ مفاتيح إدارة الخادم أو بيانات حسابات الأسرة القديمة.
4. ارفع الملفات إلى جذر المستودع الجديد، وفعّل GitHub Pages (branch `main`, folder `/root`).
5. أضف نطاق GitHub Pages في Firebase Authentication → Authorized domains. أنشئ أسرة تجريبية من الموقع، وتأكد من وجود `families/{uid}` و`users/{uid}` و`families/{uid}/members/{uid}`.
6. أنشئ حساباً تجريبياً ثانياً. تحقق أنه **لا يستطيع** قراءة بيانات الأسرة الأولى أو تعديلها؛ لا تعتمد على الواجهة وحدها في الاختبار.
7. لتمكين Push: افتح Firebase → Cloud Messaging → Web Push certificates، أنشئ VAPID Key وضع **المفتاح العام فقط** في `firebase-config.js`، وانسخ إعدادات مشروع الاختبار إلى `firebase-messaging-sw.js`. فعّل App Check وCloud Functions (غالباً يتطلب خطة Blaze)، ثم انشر الوظائف من `functions/`. يجب دمج إطلاق أحداث المستخدم في وظائف الموقع قبل حصول تنبيهات تلقائية فعلية.
8. على iPhone/iPad (iOS/iPadOS 16.4 أو أحدث): أضف الموقع إلى الشاشة الرئيسية وافتحه كتطبيق، ثم اضغط تفعيل التنبيهات. على Android استخدم Chrome لتثبيت PWA ثم امنح الإذن.
9. قبل النشر التجاري، نفّذ مراجعة خصوصية الأطفال، حذف الحسابات والبيانات، موافقات الوالدين، حدود الإرسال ومكافحة إساءة الاستخدام، سياسة الخصوصية، ومتطلبات Apple/Google، واختبار قواعد الأمان.

## بنية البيانات

- `users/{uid}`: ربط هوية العضو بالأسرة؛ لا يمكنه تعديل دوره من المتصفح.
- `families/{fid}`: إعدادات الأسرة والدولة والعملة والصلاة.
- `families/{fid}/members/{uid}`: الأعضاء والأدوار (التسجيل الذاتي يضيف الأب المنشئ فقط).
- `families/{fid}/children/{childId}`: ملفات الأطفال بدون هويات ثابتة مسبقاً.
- `families/{fid}/tasks/{taskId}`: البنود ومواعيدها.
- `families/{fid}/members/{uid}/tokens/{id}`: رموز الأجهزة، يقرأها الخادم فقط.
- `families/{fid}/events/{eventId}`: أحداث يمكن لخادم الإشعارات التعامل معها.

## ما تبقى قبل الطرح العام

- شاشة دعوة وربط حساب الأم وحسابات الأطفال الآمنة، مع وظائف `createInvite` و`redeemInvite` المتاحة كمسودة خادم فقط.
- إكمال الشات العائلي/الخاص وسجلات الإنجازات ومكافآت الأموال، ومراقبة مواعيد الصلاة والمهام فعلياً.
- جدولة Push لمواعيد المهام، وتفعيل App Check، والتحكم بمعدلات إرسال التنبيهات، والاختبارات على iOS وAndroid.
- ترجمة إنجليزية شاملة، اختبار واجهة الأطفال، ودراسة المتطلبات القانونية لحماية القُصّر.

**لا تضع المشروع الجديد في وضع الإنتاج أو البيع قبل إتمام البنود أعلاه.**


## قفل الصلاة (نسخة اختبار خادمية)
- يوجد تبويب «🕌 الصلاة». زر «صليت» **لا يعمل** قبل بداية كل صلاة أو عند/بعد نهاية المهلة، لكل أفراد الأسرة.
- يعرض التطبيق الأوقات بحسب المدينة وطريقة الحساب من خدمة AlAdhan؛ وفي حالة فشل المواقيت تُقفل الأزرار.
- عند الضغط، تُرسل العملية إلى Cloud Function `markPrayer` للتحقق من **ساعة الخادم** ثم تسجيل الصلاة.
- يتم حظر الكتابة المباشرة إلى `prayerDays` من Firestore، ولا يجوز استخدام مسار آخر لتسجيل نقاط الصلاة دون نفس التحقق الخادمي.
- هذه النسخة العامة تأسيسية؛ إنشاء حسابات الأطفال وربط علامات الصلاة بمكافآت النقاط وإشعارات Push الفعلية لم يكتمل بعد.
- لا تستبدل مشروع الأسرة الحالي بهذه الحزمة. أنشئ مشروع Firebase تجريبياً مستقلاً.

### تشغيل تجريبي حقيقي
1. أنشئ مشروع Firebase منفصلاً، وفعّل Authentication وFirestore وApp Check وCloud Functions مع خطة فوترة ملائمة.
2. انسخ إعدادات **المشروع الجديد** إلى `firebase-config.js`، ولا تستخدم إعدادات الأسرة القديمة.
3. ثبّت Firebase CLI على جهازك ثم `firebase login` ثم `firebase use --add` لاختيار المشروع التجريبي.
4. من جذر المشروع نفّذ `firebase deploy --only firestore:rules,functions` بعد مراجعة القواعد والتحقق من App Check.
5. انشر الواجهة على نطاق تجربة مستقل، ثم أنشئ أسرة واختبر تسجيل الصلاة ضمن المهلة وخارجها.
6. لا تعتبر القيود مفعلة على الموقع المنشور حتى نشر الوظيفتين `getPrayerWindows` و`markPrayer` وتجربتهما بالفعل.

**تحذير:** يتعذّر تشغيل زر «صليت» في وضع المعاينة، وأي فشل في المواقيت أو خدمة Cloud Functions يبقي الأزرار مغلقة. هذه حماية مقصودة.
